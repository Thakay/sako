# Demo: two sessions, one small change

A scripted run in a throwaway project, generated by [demo.py](../tests/demo.py).
Two live stand-in processes represent agent sessions. The test harness creates
the processes; SAKO registers them. The script runs their commands in sequence
while both sessions are active; it does not run AI agents
or measure parallel speed. Every command output comes from SAKO or Git. Paths,
dates and times are normalized, and a test checks this transcript for drift.

The request: "Add a greeting by name and show how to use it."
One session handles the code; another handles the usage guide. After the
checks pass and the work is committed, a fresh session sees the next task.
The [README illustration](assets/readme/working-together.svg) uses results
captured from this run.


## 1. Prepare the work

Install without hooks so every session command is visible. The project supplies a check for the greeting and its usage guide.

```text
$ python3 ../sako/sako.py init --client none
SAKO installed in .sako/ (local). Nothing tracked changed; the folder is listed in .git/info/exclude.
Records: .sako/work/TASKS.md and DONE.md. They are not in Git yet; git clean -x deletes them.
  Keep their history, or share them privately:  uvx sako init --repo [url]
  Commit them with the code:                    uvx sako init --shared
Hooks: none, your choice. Agents read .agents/skills/sako/SKILL.md; run start, check --gate and end yourself (python3 .sako/sako.py start --session <id>). Change the client with: uvx sako init --client claude|codex|none.
```

Set `"verify_command": ["python3", "check.py"]` in `.sako/config.json`. The two tasks cover different files in the same repository.

```text
$ python3 .sako/sako.py add "Greet a visitor by name" --done-when "The greeting prints Hello, Ada!" --scope greeting.py
T-1: open; recorded locally, not committed
```

```text
$ python3 .sako/sako.py add "Show how to use the greeting" --done-when "The guide shows a command and its output" --scope USAGE.md
T-2: open; recorded locally, not committed
```

## 3. Check and finish together

```text
$ python3 .sako/sako.py verify
greeting and usage checks passed
check: PASS in 0s; covered 3 file(s); stamp e23d67d0c54d813b -> /work/greeting/.sako/state/stamp.json
```

```text
$ python3 .sako/sako.py close T-2 --session demo-docs --evidence "USAGE.md shows the command and expected greeting; check.py passes"
T-2: done; recorded locally, not committed
```

```text
$ python3 .sako/sako.py close T-1 --session demo-code --evidence "greeting.py prints Hello, Ada!; check.py passes"
T-1: done; recorded locally, not committed
```

Both sessions use the same passing check of the final files. The scripted code session commits the agreed changes. SAKO never commits for it.

```text
$ git add -- greeting.py USAGE.md
```

```text
$ git commit -qm "Add the named greeting and usage guide"
```

```text
$ python3 .sako/sako.py check --gate --session demo-code
SAKO gate: clear
```

```text
$ python3 .sako/sako.py check --gate --session demo-docs
SAKO gate: clear
```

## 4. Pick up in a fresh session

Record the next request before both sessions check out of SAKO with `end`. This removes their presence records.

```text
$ python3 .sako/sako.py add "Handle a missing name" --done-when "A missing name prints a usage hint" --scope greeting.py
T-3: open; recorded locally, not committed
```

```text
$ python3 .sako/sako.py end --session demo-docs
```

```text
$ python3 .sako/sako.py end --session demo-code
```

A fresh agent session is opened in the coding tool. It runs `start` to check in with SAKO and gets the current check evidence and the next task from the files.
